# 颐听 App · 修订后的完整开发与发布流程

> 本流程替换旧版蓝图。**T01、T02 都在当前 `2.0` 开发分支中完成**；之后从 `3.0` 开始，按任务编号和版本号逐步推进。

## 一、项目定位与产品范围

**颐听**是给爸妈使用的大字版听戏、听书、看书工具，核心原则是**本地优先、打开即用、操作简单**。

- 不强制登录，不把联网作为本地功能的前提。
- 不做广告、推荐算法、社区等非核心功能。
- 广播需要联网；其他本地内容在无网时仍应可用。
- 首版功能集中在本地音频、广播、TXT 阅读、续播、收藏和基础设置。

## 二、页面和导航

### 底部固定三个 Tab

1. **首页**：最近在听、醒目的“听广播”和“看书”入口，以及设置入口。
2. **听戏**：本地戏曲/相声音频、分类、搜索、收藏。
3. **听书**：本地有声书、章节列表和续播。

“看书”和“听广播”是首页首屏可见的入口，不藏在菜单或多层页面里。播放页提供足够大的播放控制，并能回到内容列表。

### 大字和易用性

- 品牌强调色：`#FA2D48`。重要文字优先使用高对比度的文字与背景组合；不要把小字直接放在红底上。
- 正文以 **20sp 左右**为目标，标题从 **28sp** 起；辅助信息也要清晰可读。
- 设置提供标准、大、特大三档字号，并尊重系统字体缩放。放大后不得裁切、遮挡或无法操作。
- 一般可点击区域至少 **48dp**，主要播放/暂停按钮至少 **96dp**；列表项目标高度至少 **72dp**。
- 常用的倍速、定时和播放控制应直接显示，不依赖难以发现的菜单。
- 核心流程支持 TalkBack；验证小屏幕、大字体和横屏下的布局。

## 三、技术与数据约定

### 平台和架构

- Kotlin、Jetpack Compose、Material 3，最低支持 Android 8（API 26）。
- 应用名：**颐听**；包名：`com.yiting.app`，永久不变。
- 保留现有八模块：`app`、`core-ui`、`core-data`、`core-player`、`feature-radio`、`feature-book`、`feature-opera`、`feature-read`。
- `app` 负责组合页面和导航；`feature-*` 实现功能；`core-*` 提供共享能力。功能模块不能互相形成循环依赖。
- Gradle、AGP、Kotlin、KSP 版本要彼此兼容，并集中管理；使用仓库中的 **Gradle Wrapper**，CI 统一运行 `./gradlew`。
- 使用 Google Maven 和 Maven Central 等可靠仓库；除非确有必要，不依赖额外镜像。

### 本地文件、权限和数据

- 通过 MediaStore 查询本地音频，不申请不必要的宽泛存储权限。
- 有声书目录及 TXT 文件由用户通过系统文件选择器选择；需要跨重启访问时保存系统授权的 URI。
- 按 Android 版本处理媒体权限、用户拒绝权限、没有文件和文件不可访问等状态。
- Room 保存最近播放、播放进度、收藏、用户分类、阅读位置和必要的设置；定义数据库迁移策略。
- 用户的播放记录、收藏和阅读位置默认只存本机；不增加未说明的数据上传或遥测。
- 明确支持的音频格式、TXT 编码和不支持文件时的提示方式。

### 播放、广播和阅读

- 使用 Media3、前台播放服务和 MediaSession，测试息屏播放、通知、音频焦点、耳机与蓝牙线控。
- “重新打开 App 可恢复上次媒体及位置”作为恢复目标；不承诺系统杀掉进程后播放仍持续。
- 电台只使用确认可用且有权使用的来源。数量以实际验证结果为准，不预先承诺固定 10 个；维护流地址、来源、使用条件和最近验证时间。
- 电台断网、超时或地址失效时显示清楚的大字错误、重试及切换入口，不能白屏。
- TTS 依赖设备语音引擎，须检查中文语音是否可用；不能使用时要解释原因和可行操作。
- 定时停止要明确规则：暂停、切歌时倒计时如何处理，并在界面显示剩余时间。

## 四、分支和版本规则

### 当前分支安排

- `dev_2.0`：当前开发分支，**T01 和 T02 均在这里完成**。
- `release_2.0`：T01、T02 验收通过后的累计稳定分支。
- `main`：对外稳定分支，只从验收后的 `release_2.0` 合入。
- `dev_1.0`、`release_1.0`：保留为历史分支，不再用于这轮开发。
- 完成 T02 后，从经过验收的 `release_2.0` 创建 `dev_3.0`；以后依次按 `dev_3.0`、`release_3.0`，再到 `dev_4.0`、`release_4.0` 推进。

T01 和 T02 的版本标识分别是 **1.0** 和 **2.0**，但它们的代码都落在当前 `dev_2.0` 开发线上。不要为了匹配 T01 的编号而把新代码回移到旧 `1.0` 分支。每完成一个任务，提交到对应稳定分支的 PR 仍须经过验收。

### 版本号规则

- T01 发布版本：`1.0`；T02 发布版本：`2.0`；T03 起依次为 `3.0`、`4.0`，以此类推。
- `versionName`、发布标签和验收记录统一使用对应版本号；每次发布都递增 Android `versionCode`。
- 开发中可以使用开发构建，但正式发布包必须使用已验收版本号。
- 所有版本沿用相同的 `applicationId` 和受保护的签名身份；签名密钥不能提交到仓库，必须安全保管并备份。

### PR 流转

- T01、T02 开发在 `dev_2.0`；各自验收通过后，以 PR 合入 `release_2.0`。
- T02 完成后，从 `release_2.0` 创建 `dev_3.0`，后续任务按对应版本开发和验收。
- 稳定发布时，再通过 PR 将已验收的 release 分支合入 `main`。
- 不直接向 `main` 或 release 分支提交未经验证的代码。若现有 release 分支含有旧的未验收内容，先核实差异和历史，再决定如何处理；不要未经检查强行覆盖或重写历史。

## 五、每项任务的固定循环

1. 明确任务范围、文件清单、验收标准和可能涉及的权限、数据变化。
2. 按任务编号提交完整代码到当前开发分支，提交信息使用 `[T0X] 描述`。
3. GitHub Actions 使用 Gradle Wrapper 执行：
   - `./gradlew assembleDebug`
   - 单元测试
   - Android Lint
   - 上传构建 APK Artifact  
   涉及界面和设备行为的任务，还应运行相应的模拟器测试。
4. CI 通过后安装 APK，按任务验收清单实测；记录操作步骤、设备型号、Android 版本和结果。
5. 失败时提供完整 Actions 错误日志或可复现的操作现象，修复后重新运行 CI 和测试。
6. 全部通过后开 PR：`base: 对应 release 分支 ← compare: 对应 dev 分支`。检查差异和检查结果后合并。
7. 每次发布都从对应的已验收 release 分支生成正式包，更新版本信息和发布说明。

CI 绿勾是必要条件，但不能代替真机验收。签名密钥及其他敏感值不得写进代码或提交到仓库；需要 CI 签名时使用受保护的 Secrets。

## 六、任务清单与验收标准

### T01 · 版本 1.0：项目骨架与基础导航

**开发分支：`dev_2.0`**

- 整理构建配置和依赖版本，确认八模块构建关系。
- 加入 Gradle Wrapper 和基础 CI。
- 完成应用名、包名、基础主题和首页/听戏/听书三 Tab 占位界面。

**验收**：干净检出后 CI 可构建并上传 APK；安装后显示“颐听”；包名为 `com.yiting.app`；三 Tab 可切换；主色、字号和按钮尺寸符合约定。

### T02 · 版本 2.0：首页、基础体验与本地数据

**开发分支：继续使用 `dev_2.0`**

- 完成首页“最近在听”、听广播和看书入口、空状态和设置入口。
- 建立 Room 表结构及迁移方案，包括播放记录、收藏、媒体条目和阅读位置等必要数据。
- 完成本地音频查询与文件选择器接入，处理权限拒绝、无内容、文件不可访问等状态。
- 为后续播放内核定义清楚的数据接口。

**验收**：首页入口清晰；首次安装、拒绝权限、无文件和有文件时都能正确显示；本地数据可保存和读取；大字号下界面不裁切；无内容时不白屏。

### T03 · 版本 3.0：播放内核与本地音频

**开发分支：从验收后的 `release_2.0` 创建 `dev_3.0`**

- Media3 播放服务和 MediaSession。
- 播放/暂停、上一首/下一首、进度、倍速、定时停止。
- 保存与恢复播放位置，处理音频焦点、息屏、耳机及蓝牙线控。

**验收**：本地音频完整播放；播放控制、息屏和线控在真机通过；重新打开 App 可恢复媒体及位置；播放失败时有明确提示。

### T04 · 版本 4.0：听戏与广播

- 完成本地音频列表、候选戏种分类、手动改分类、收藏和置顶。
- 接入经过验证、可合法使用的电台来源；提供加载、播放、失败、重试和切换状态。

**验收**：用户可以修正分类；收藏即时生效；至少有一个经验证可用的电台；断网或播放失败时仍有清楚的操作入口。

### T05 · 版本 5.0：听书与看书

- 有声书章节识别、章节列表、续播和倍速。
- TXT 导入、编码处理、字号、行距、翻页、阅读位置、夜间模式及 TTS 可用性检查。

**验收**：有声书选章和续播可用；TXT 退出重进后位置正确；字号调整不裁切；中文 TTS 不可用时有清晰说明且不崩溃。

### T06 · 版本 6.0：设置和无障碍打磨

- 全局字号三档、定时默认时长、清理可清理缓存、关于页面。
- TalkBack 核心流程；统一加载、空、错误及重试状态。

**验收**：三档字号在首页、列表、播放和阅读页面生效；TalkBack 可完成核心播放流程；各种异常状态都有可理解的提示和可操作的入口。

### T07 · 版本 7.0：回归与正式发布准备

- 回归 T01–T06；清理调试代码；完善 README、截图、安装方式、权限说明、支持格式和常见问题。
- 检查签名、版本号、升级和安装流程；记录已知问题。

**验收**：构建、测试、Lint 和任务回归通过；Release 包成功生成；签名密钥没有进入仓库；新装与覆盖安装的核心流程正常。

## 七、当前执行顺序

1. 在 `dev_2.0` 完成 T01（版本 1.0）并按清单验收。
2. 继续在同一 `dev_2.0` 完成 T02（版本 2.0）并按清单验收。
3. 两项分别经过 PR 验收后，累计进入 `release_2.0`。
4. 从验收后的 `release_2.0` 创建 `dev_3.0`，开始 T03（版本 3.0）。
5. 后续按任务编号、版本号和对应开发/稳定分支继续推进。
